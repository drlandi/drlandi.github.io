Passei 25 anos mantendo no ar sistemas de missão crítica — redes wireless de nível carrier,
infraestrutura de sinalização, bancos de dados de pré-pago rodando em Solaris e HP-UX, em
operações de telecom em seis países. A disciplina que vem desse mundo — gestão de SLA, ITIL,
eTOM, a premissa de que falha não é hipótese — é a base de tudo o que construo aqui.

Agora estou me reciclando de forma deliberada para desenvolvimento de IA e engenharia de
software moderna, sobre bases cloud-native. Isso significa:

- **Engenharia de IA** — inferência local de LLMs (um runtime em C sobre o llama.cpp feito
  para caber em um notebook de 8 GB), padrões de decisão tipada para aplicações baseadas em
  LLM e uso de ferramentas de IA em trabalho pedagógico real.
- **42 São Paulo** — um currículo intensivo de programação de sistemas, baseado em projetos:
  C, algoritmos, gerenciamento de memória, internals de Unix/Linux, código revisado por pares,
  sem aulas expositivas e sem atalhos.
- **Arquitetura AWS na prática** — WAF, CloudFront com failover, API Gateway, Lambda,
  DynamoDB, SQS, CloudWatch. Não são tutoriais — são sistemas reais, testados, com injeção
  de falhas.

Também sou professor. No CIEBP, uma unidade educacional especializada dentro de uma escola
pública estadual de São Paulo, crio séries de atividades que levam o pensamento
computacional — programação desplugada, letramento em IA — para salas de aula que
normalmente não têm acesso a isso.

Se quiser a versão longa, meu currículo está [aqui](/curriculo.pdf) — mas este site existe para
mostrar o trabalho diretamente, em vez de descrevê-lo.
